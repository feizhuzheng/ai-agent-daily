# dif.sh：把 feature flag 写成仓库里的 markdown，专门给 agent 看

> 来源 / Source: https://clauday.com/zh/article/ce37b725-cb76-4849-bf28-ddb28eb708ca

周六的 Product Hunt 日冠军（323 票）是 dif.sh（https://dif.sh）。它把 feature flag 和 A/B 测试从 SaaS 仪表盘里拿出来，变成仓库里的 markdown 文件。每个实验一个 .md——frontmatter 装假设、受众、变体，正文写文档——放在 experiments/active/ 里，做完了挪进 experiments/concluded/。CLI（dif new、validate、build、conclude）把一切编译成带类型的客户端，构建期用互斥组揪出打架的实验，生产环境从不外呼任何服务。PR review 顶替审批流程，git 就是审计日志。

它为什么现在发布、为什么能赢下这一天：agent。coding agent 在会话开始时读一份生成的 context.json，直接继承之前所有实验学到的东西。还有按界面分的 markdown 日志——这个按钮测过四次、每次动了什么指标——于是下一个提 UI 改动的 agent 是站在组织记忆上开工，而不是从零重新发现。

这个"继承"细节才是真正的产品。每个用 coding agent 的团队都有同一个无声的坑：agent 兴冲冲重新设计一个两个季度前就被 A/B 测试毙掉的方案，因为测试结果躺在一个 agent 从没见过的仪表盘里。把已结束的实验变成仓库里的文件，等于把死掉的测试变成护栏。

拉远看，这又是今年最清晰的模式：技能变成了 markdown，agent 指令变成了 AGENTS.md，现在轮到实验了。所有想在 agent 时代活下来的东西都在往仓库里搬家，因为仓库是 agent 唯一保证会读的表面。核心免费可自托管，付费云版多一个带置信区间的仪表盘。
