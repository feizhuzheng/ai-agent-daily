# Spotify 给 Claude Code 配了个便宜实习生，token 立省 90%

> 来源 / Source: https://clauday.com/zh/article/400d8e6f-0fcf-407b-9b4e-589c8fd5fe98

周末冲上 HN 首页的一篇 Spotify 工程博客，给出了本季最可复制的 agent 成本数字：Claude Code 的批量文件读取平均省了约 90%（https://engineering.atspotify.com/2026/9/portal-by-spotify-cut-my-claude-code-token-usage-by-90，作者 Dimitri Mazmanov，9 月 3 日发布）。窍门不是更好的模型也不是更大的缓存，是分工：别再让你最贵的模型干读文件的活。

方案跑在 Spotify 内部平台 Portal 上，它的 AiKA Modes 是跑在临时运行时上的声明式 agent——Lambda 风格，零基础设施管理。两个廉价模式用 temperature 0.2 的 Gemini 2.5 Flash 干粗活：bulk-reader 消化一堆大文件回答一个问题，code-writer 照着现有模式批量产出样板代码、测试和配置。Claude 只保留推理和编辑，实习生包揽所有 I/O。

最值得偷的是强制执行那一环。一个 PreToolUse 钩子物理拦截超过 350 行的文件读取，直接 block——harness 不是拜托 Claude"记得委托哦"，而是让昂贵路径根本走不通。skills 文件告诉模型何时移交、怎么移交，bash 包装脚本负责管道。插件叫 shunt，已开源：https://github.com/sorantis/portal-ai-plugins。

这是路由这条线杀进了循环内部。过去一个月的数据点都是按请求路由——换便宜模型、把 agent 编译掉、或者像 caveman 那样少说话（https://clauday.com/zh/article/9f261734-1d64-420c-b2d5-1deaf8364a9d）。Spotify 按工具调用路由：每一次读取都是一个路由决策。原来 90% 的钱，一直躺在读文件里。
