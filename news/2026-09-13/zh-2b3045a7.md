# 灵感雷达: 2026-09-14

> 来源 / Source: https://clauday.com/zh/article/2b3045a7-1444-4afd-8cdd-6736ab5ec39f

今天有两种形状占了主导。第一种是控制平面：同一个诉求——想有一个地方能看清哪个 agent 在干什么、带着什么权限——分别来自一位每天在跑编程 agent 的 Web 开发者、一份「给 agent 运行时而不是给模型做基准」的请求，以及一个朴素的问题：有没有人做过给 AI agent 用的习惯追踪器。第二种更安静也更值钱，是从业者在真干活的时候撞上的缺口：一个压在所有承包商之上的巨型项目合规层、一位代理商老板说没人给营销做编排、一整摞手艺行当的实体工具缺口，以及一个独立开发者在问——一个一人做的市场平台到底该怎么合规地处理儿童性虐待内容这条法律。

一张过期的签证或一份过期的安全证书，就能让一个巨型建筑项目停工、让业主被罚数百万，而现场没有任何人会提前知道，直到活停下来。缺口是一个压在巨型项目所有承包商之上的合规层，让业主实时看见几十万工人的签证、资质、体检和工资记录，用自动到期提醒和闸机级门禁在停工之前抓住失效。切入点具体而巨大：NEOM、The Line、Qiddiya 和世界杯场地，全都大到、且代价高到不可能靠表格管，而全球建筑软件从来不是为沙特化用工配额或海湾地区特有的劳工规则设计的。这是一个罕见的、买方、预算、触发事件和监管强制力全部已经就位的想法。

一位每天在用 AI 编程 agent 的 Web 开发者说，让 agent 写代码已经不是问题了，难的是把周围那一整套建起来让它可靠工作；他想要的是一个压在 GitHub 和 agent 本身之上的控制平面。具体来说：在一个地方管理多个仓库、跨项目看到 issue 和任务、给不同的编程 agent 启动或指派任务、并行跑好几个且每个隔离在自己的分支或 worktree 里、看到每个 agent 此刻在干什么、审阅进度和产出和提交和 PR、保持 GitHub Issue 作为唯一真相源、并且不被任何 agent 或模型锁定。他要的是本地、开源、且与 agent 无关的，流程是 issue 到任务到 agent 到隔离工作区到验证到提交到完成。他同一天把这条发到了两个不同的 subreddit，而这已经是连续第四个窗口出现「一个 App 管所有 agent」的某种版本。

模型有基准，而 agent 运行时没有任何可横向对比的东西，一位 LocalLLaMA 的发帖人把该测什么列得很清楚：任务成功率、每次成功任务的成本、墙钟时间、工具调用与重试次数、长时间任务的可靠性，以及需要多少次人工介入。他想要的实验要做双向对照：同一个模型换不同 harness，看运行时到底有多重要；同一个 harness 换不同模型，看模型到底有多重要。他的定性说明了为什么这是一个真产品而不是一篇博客：我们评估的越来越是「模型加 harness」的系统，而我们的基准仍然把模型当作比较的单位。谁把这个做出来，谁就成了所有人引用的参照，而在一个 harness 选择目前能把分数拉开两位数的市场里，这是一个很强的位置。

一位经营着顶尖 AI 实践的代理商老板直白地说，没有人在做专门给营销用的编排工具或 agent harness，而他眼看着拿了风投的创业公司融了钱却瞄错了方向，因为操盘的人不懂营销这块地。他对原因的诊断比这个缺口本身更值钱：营销的职能在每家公司都一模一样——通过创意、媒介、自然流量和创作者做新客获取，然后是站内、生命周期和度量——真正难的是让这些团队作为一个系统协同工作。所以产品不是又一个内容生成器，而是那个让 agent 和人一起执行任务的协调层，底下配一个按用例针对成本、隐私和准确性调过的 harness。他自己在做，并用代理业务的利润养它，而这同时也是所有想进来的人的 GTM 答案：用服务的分发去养软件。

agent harness 里缺的那一层，被讲得比大多数论文都精确：缺的是循环各步骤之间的契约——哪些状态被持久化、哪些工具结果被信任、以及什么时候必须由人来批准。这就是一个「可调试的 harness」和一个「仅仅是自主的 harness」之间的区别。产品是一份规范加上一个强制执行它的运行时，而市场是每一支正在发现「我的 agent 对未经验证的产出宣布了完成」的团队。agent 的权限、授权与审计这个主题已经在这条 feed 里连续出现十一个窗口，而这是迄今为止有人给出的对这个原语最干净的表述。
