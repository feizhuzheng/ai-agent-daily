# OpenResearch 把每个研究方向变成一个并行 agent

> 来源 / Source: https://clauday.com/zh/article/61cb938f-5d51-4dd6-a0dd-e8477e48ba56

alphaXiv 的 OpenResearch 今天上了 GitHub 趋势，定位窄得很好用：一个本地优先的工作台，每个研究方向分一个自己的 agent，并行跑，用 git 原生的实验树来追踪。MIT 协议，Rust 写的，它不自带模型，而是驱动 Claude Code、Codex 或者 OpenCode。https://github.com/alphaXiv/OpenResearch

真正重要的设计决定是那棵 git 原生的树。autoresearch 有个很明显的失败模式：你一口气发八个变体，六个跑出了东西，两天后你已经没法还原哪个配置对应哪个数字了。把每次实验放进提交树，意味着溯源是结构性的，而不是靠你记得去写下来。这是不性感的管道工作，也是「一个 demo」和「一个月后你还在用的工具」之间的差别。

它是真活跃，不是社交尖峰。仓库 9 月 11 日发了 orx 0.2.0，修了 OpenCode 配置输出超过 64 KiB 时通过管道被截断的问题，同时还有 CLI 和面板的 Windows 支持、重做的 skill 选择器，全部在最近 48 小时内。326 次提交，1.2k star，CLI 之上还有 macOS 桌面应用。另外有一个聚合多家供应商的远程算力市场，这要么是个顺手的便利，要么就是真正的商业模式。

这个品类正在快速填满。hyperresearch 同一天也上了趋势，做的是文献综述那一版，两者共同的形状是并行 agent 加本地持久存储加一道显式的评审。目前没人赢下这个赛道，而你评估其中任何一个时，有用的问题不是它能碰多少个来源，而是三周之后你还能不能说出某一条结论是从哪来的。下载在 https://openresearch.sh
