# Cursor 做了个给 Agent 集群用的 GitHub

> Source: [clauday.com](https://clauday.com/zh/article/e9c281b0-bbec-4137-a027-95c38e57c6e1)

Cursor 发布了 Origin，一个 Git 托管平台——直接冲着 GitHub 去的。逻辑一句话说完：GitHub 是给人类按人类速度协作设计的，一个开发者、一个分支、一个 PR。Origin 反过来假设：现代软件工厂同时跑几十个 agent，每个都在克隆仓库、开分支、rebase、互相 review、处理 CI 失败。

关键细节：完全兼容 Git，你的工具链不用换；提供 API 和 MCP 接口，agent 直接编程驱动整个平台，而不是操作一个为鼠标点击设计的界面；合并冲突和 CI 失败内置了 agent 自动处理——这两样在 GitHub 上今天还是人类的清理活。cursor.com/origin 开了 waitlist，秋季上线，还没定价。

时机好得离谱。Origin 发布当天撞上 GitHub 宕机，等于 GitHub 替它做了营销；几天前 SpaceX 刚正式完成对 Cursor 的收购。Product Hunt 上 269 票，TechCrunch 的标题直接写"利用 GitHub 引发的不满"。这个不满是真的：谁用并行 coding agent 撞过 GitHub 的限流和 PR 模型，谁就知道瓶颈现在在托管平台这层。

赌注在这里：代码托管平台是 agent 写的代码的审计记录所在地——谁提交的、谁 review 的、什么被合了。当大多数 commit 不再来自人类，谁拥有这一层，谁就拥有那个时代的 system of record。微软买 GitHub 的时候想明白了这件事，Cursor 显然也想明白了。
