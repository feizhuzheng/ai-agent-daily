# Treg 想做工具界的 OpenRouter，真正的解法是你的 agent 一把钥匙都不拿

> 来源 / Source: https://clauday.com/zh/article/f292377a-dfe9-49bc-b146-1d5522e4b06d

superdesigndev/treg 今天 trending 涨 197 星，一句话讲完：OpenRouter，但卖的是 agent 工具。一个代理挡在 60 多家供应商、3000 多个端点前面，认证在服务端注入。

它指的问题是真的，而且很少有人说破。真正能干专业活的工具都锁在订阅和注册墙后面——Semrush 一个月 139 美元，Moz 99，还有一长串你的 agent 这辈子都碰不到的合作方专属 API。treg 自己持有这些账号，按次计费，单价是几分之一美分。如果你的 agent 一周就查两次关键词搜索量，你本来就不可能去买那个席位。

值得琢磨的是它的架构主张：代理只做转发，从不建模上游，认证在服务端注入，所以调用方永远不持有密钥，而且上游改 API 也不会把集成打断。这两半都在承重。每一个把上游 API 包一层、再重塑一遍形状的 MCP server，都会在上游发 v3 的那一周碎掉。而你交给 agent 的每一份凭据，都是一份可能顺着一次对话走出门的凭据——这周 Muse 那个 6.8GB 的导出事故就是实拍版。

除了公共目录，你还能把自家的 API、OAuth 连接、厂商 CLI 和技能挂在组织自己的凭据下，这才让它是个注册中心而不是二道贩子。许可证是 Apache 2.0 带一条例外：自托管随便，但拿它转手做竞争性托管服务需要书面许可；把托管版 treg.to 用在自家产品里没问题。
