# 腾讯 teamai-cli：把团队的规矩变成一个 git 仓库

> 来源 / Source: https://clauday.com/zh/article/7b079494-af06-4ff1-b23b-7ca579aa91cc

teamai-cli 一天涨了 563 颗星，它瞄准的问题正是多数团队用 agent 到第三个月会撞上的那个：全组每人用的 agent 都不一样，Claude Code、Codex、Cursor、CodeBuddy、OpenCode 各来一套，每一套都带着自己的规则、自己的 skill、自己对你代码库的理解，谁的上下文都传不到别人那里。腾讯的答案是把团队共享知识变成一个 git 管理的产物，让所有 agent 都读它。

机制刻意做得不刺激：skill、规则、文档、环境变量、hook，全部通过 push、review、merge、pull 分发。你团队的编码规范要过 code review。整个设计决定就这一条，而且是对的——因为大家现在实际在过的日子是：一个 CLAUDE.md，一个人改，别人根本不知道它变了。

两个 beta 功能野心更大。Team Context 抓取它称为「摩擦式学习」的东西，也就是 agent 卡住的那些时刻，并让后续会话里的其他人能召回。Team Improvement 加了使用分析和会话追踪，用来防止知识库腐烂——这是没人愿意谈的失败模式：一个没人修剪的 skills 目录，一个季度内就会变成负债。MIT 协议，695 次提交，昨天还在更新。

skills 这个货架已经整合了好几个月，从个人仓库（https://clauday.com/zh/article/6d4a0b8b-fd5a-487d-9d71-936dd724afaf）一路到占满整个 GitHub trending（https://clauday.com/zh/article/0c470666-306a-4aea-9833-c53a95254dd2）。这次是同一个轮子转到了公司这一格：一旦 skill 变得要紧，就得有人来管它的发布流程。https://github.com/Tencent/teamai-cli
