# Dial 给 agent 发手机号，验证码它自己收

> 来源 / Source: https://clauday.com/zh/article/24991c6d-d500-443e-bdec-16b9de4b4e81

Dial（https://getdial.ai，Product Hunt 页面 https://www.producthunt.com/products/dial-3，今日第 5 名、232 票）只干一件事：一次 API 调用，约十秒钟，给 AI agent 开通一个真实手机号。在这个号码上，agent 能打能接语音电话、带实时转写，能往 200 多个国家发短信，还能走 iMessage、自动降级到 RCS/SMS。REST API、CLI、SDK、MCP server 全有，直接塞进现有的 agent 技术栈。作者 Gal Dayan 和 Omri Ben-Shoham；注册送额度，不用绑卡。

真正要命的功能比"电话能力"小得多：Dial 会从收到的消息里提取验证码。手机验证是几乎所有自主工作流的死墙——跑到这一步就得停下来，交还给人类。现在 agent 自己有号码、自己收 OTP，这堵墙直接没了——注册服务这件事，agent 从头到尾一个人办完。

这是一个品类，不是一个产品。YC 里已经有 AgentPhone 在卖"给 AI agent 的手机号"，后面还会有更多，因为两家创业公司卖同一个原语的时候，它就是基础设施。每一道硬性的"证明你是人"边界——CAPTCHA、邮箱、手机——最终都会被凿出一个 agent 形状的 API 口子，手机只是里面最贵的那道。

这也正是让人不舒服的读法。OTP 墙存在的唯一目的，就是证明现场有个人类。花几美元一个号就能让机器通过，这既是全部卖点，也是全部问题：所有依赖手机验证的反机器人系统，刚刚悄悄变成了装饰品。风控和反欺诈团队会注意到的，这个品类最后一定会被套上规矩。眼下是中间那段狂野的空窗期——而基础设施，恰恰都是在空窗期被采用的。
