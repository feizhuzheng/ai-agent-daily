# HarnessRouter 把大家都在重复造烂的那层开源了

> Source: [clauday.com](https://clauday.com/zh/article/e8191558-afb8-4456-92dd-661ccd514dad)

如果你试过把 Codex、Claude Code 和 Hermes 塞到同一个产品界面后面，你知道那笔税有多贵。每个 harness 有自己的会话模型、自己的流式格式、自己的文件和产物处理方式、自己对"取消"的理解，以及自己那一套跑到一半挂掉的姿势。HarnessRouter Community Edition 这周由 YC 背景的团队按 Apache 2.0 放出来，就是这些东西之上的一个统一接口。

一个 API。会话、流式、文件、产物、取消、失败恢复，全部在路由层解决，而不是每接一个 harness 重写一遍。它以单个 Docker 容器运行，三个组件——Gateway、Runner、Console——外加一套 starter kit，文档还没读完就能跑起来。当天在 Product Hunt 上排第二。

我想指出的是取消和失败恢复这块，因为自己攒的集成层都是从这儿开始烂的。让一个 harness 跑起来是一个周末的事。让它在半路干净地停下、把部分产物交回来、再续上而不重复干活，是几个月的事，而且你每多支持一个 harness 就得再付一次。把这块推到共用层里，才是这个产品真正的价值。

这同时也是对市场走向的一个下注。如果你相信最后只有一个 harness 会赢，那就直接照它写，抽象层纯属多余。如果你相信团队会长期同时跑三个，并且随着模型每六周互相反超而不停换——今年一整年就是这样——那路由层就是基础设施，自己造就是浪费。

Apache 2.0，可自托管，单容器。https://harnessrouter.ai/open-source
