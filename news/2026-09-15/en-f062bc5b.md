# Ideas Radar: 2026-09-16

> 来源 / Source: https://clauday.com/article/f062bc5b-d0c0-4c87-9602-0864398ae1ab

The strongest signal today is that the verification half of the AI stack has no products in it. Capability compounds and verification does not, and the same gap showed up from four unrelated directions in one window — frozen external state so a trace can actually be replayed, a replayable event log carrying policy decisions and rollback points, explicit session ownership so the fastest participant does not win by default, and specs that state the failure they are preventing rather than only the behaviour they want. Away from agents, the consumer end produced the widest reach of the day with a single sentence about a microwave, the trades vein surfaced two more controlled-depth cutting problems that practitioners have diagnosed precisely and nobody is tooling, and two separate posters independently built the same validation method: check the search bar before you build anything.
---
Recursive self-improvement is being read as a capability curve when it is actually a ratio. Capability compounds: models now write training code, generate data, design experiments and run their own evals, and every part of that loop got a multiplier. Verification did not. It is still humans reading reports and forming judgment, and it has never doubled once. The structural problem is that verification cannot recursively self-improve, because you cannot check an accelerating system using the accelerating system. The product opportunity is everything that can be verified by construction rather than by judgment — what context entered a run, what it acted with, what left. Facts about architecture, not opinions about intelligence. Everyone is arguing about the numerator. Nobody is building the denominator.

A trace shows what the agent decided, not what the world returned. Replay it and the tool responses come back different — latency shifted, API state shifted, data shifted. So the missing layer is frozen external state, and without it traces are forensics rather than reproducibility. That distinction is worth a product: everyone currently building agent observability is selling forensics and calling it reproducibility, and the difference only shows up the first time you try to re-run a failure and cannot.

A method rather than an idea, and it is worth copying. Before building anything, type your app description into the app store search bar: if it does not autocomplete, nobody is typing it. Then check who ranks — ten apps with fifty thousand ratings is a fight, three weak apps with two hundred ratings is a gap. Use the words users type, not the words you would use, because your "focus companion" is being searched as "study timer." The caveat he adds is the sophisticated part: ranking is mostly about how the listing is written rather than app quality, and half the top results got there with competitor brand names stuffed into a hidden keyword field, so a crowded search page is not proof the category is actually served well.
