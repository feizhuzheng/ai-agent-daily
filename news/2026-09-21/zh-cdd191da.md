# Meta 的购物 agent 上线 12 天，被亚马逊关在门外

> 来源 / Source: https://clauday.com/zh/article/cdd191da-da63-41d6-b7aa-2c5ba3f68a98

Meta 9 月 8 号发了 Muse。9 月 20 号晚上，任何试图通过它在亚马逊完成下单的人都会看到一个弹窗：未经授权的 AI agent 继续访问违反亚马逊使用条款，而客户已经同意过该条款。从发布到被封，十二天。

亚马逊给的理由值得逐条看，因为它们是技术性的，并且没在谈竞争。亚马逊说 Muse 在站内浏览时隐藏自己的身份，并且看起来在收集和留存客户凭据，这会让它拿到账户页和订单历史，全程亚马逊不知情也没同意。亚马逊还说，在拔线之前先找过 Meta，要求把 amazon.com 从 Muse 的范围里去掉。Meta 的回应是 Muse 看不到密码和支付方式，共享凭据存在安全存储里。

两边可以同时说的都是真话，这恰恰就是问题。Meta 在描述 Muse 拿凭据干了什么。亚马逊在描述自己能观测到什么，也就是一个它无法归因到人的已登录会话。从服务端看，一个拿着你密码的 agent 和一个今天心情不好点得飞快的你，是无法区分的。HTTP 里没有一个字段写着「现在是机器在开车」。

这才是真正的故事，而且比这两家公司大得多。今天所有的购物 agent 都靠握着你的凭据假装是你在跑，因为没有任何一家零售商提供过一条路，让 agent 表明自己是谁、被授权做什么。agent 商务的身份层根本不存在，所以只剩两个动作，冒充或者被封，亚马逊刚刚把第二个动作做了一次规模演示。谷歌的购物 agent 和 Perplexity 的 bot 此前都吃过同一招。

接下来要看亚马逊做什么，而不是说什么。封锁便宜且临时。有意思的版本是一条付费的、带认证的 agent 通道，由亚马逊决定谁能进、按什么条件进，闸口的价格变成一个报表科目。那是收费站，不是安全策略，一旦出现，整个 agent 商务品类一夜之间变成一场租金谈判。
