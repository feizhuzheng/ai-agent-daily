# Agent-Reach 让你的 agent 不用一个 API key 就能看推特和油管

> 来源 / Source: https://clauday.com/zh/article/c9c0180d-126e-48ca-a384-6a82bbf4e263

今天 GitHub Trending 上涨得最猛的 agent 仓库是 Agent-Reach，单日涨约 640 星，总数 81200，MIT 协议，地址 https://github.com/Panniantong/Agent-Reach 。标语就是产品全貌：给你的 AI agent 一双看见整个互联网的眼睛——读取和搜索 Twitter、Reddit、YouTube、GitHub、B 站、小红书、Facebook、Instagram、LinkedIn、RSS 和普通网页，一个 CLI，零 API 费用。

做过 agent 的人都撞过这堵墙。你让它说说这个 YouTube 教程讲了什么，它拿不到字幕。你问一个 Reddit 帖子，它拿到一个登录页。你问一条推文，撞上 twitter.com 跳 x.com 的重定向，什么都没有。每一个单独都能解决，而每个解法都是另一套 API、另一个 key、另一套限流、另一张账单。Agent-Reach 的答案是一个 CLI，给每个平台维护主用和备用两条访问路径，一条挂了自动切换，另外还有个 agent-reach doctor 命令，告诉你哪些通道现在是通的、其他为什么不通。

doctor 这个命令是即便你不装这个工具也该偷走的部分。抓取路径腐坏是常态，而典型的失败体验是 agent 默默返回空，然后编一个答案给你。一个能汇报自身通道健康状况的工具，把一个无声的错误答案变成了一根看得见的断管。这是设计模式，不是功能。

安装是冲着 agent 设计的而不是人：你把安装脚本的一个 URL 丢给 agent，它自己搞定依赖、系统检查和配置。Cookie 和 token 留在本地。兼容 Claude Code、OpenClaw、Cursor 这类外壳，部分通道走 MCP，包括 Exa 搜索和 LinkedIn。375 多次提交，7100 个 fork，是个真项目。

上下文让它比一个顺手工具要重一点。[谷歌刚刚改了搜索结果链接，让每次点击都多花一个请求](https://clauday.com/article/aefe8e72-b836-4119-8adc-d21145eb36fe)，整个平台层正处在对自动化读取者的长期挤压中。一个带自动故障转移的免费抓取聚合器，按设计就站在这场仗的一边，而诚实的提醒是：整个东西的耐久性，取决于那些备用路径里的每一条能不能熬过下一轮反制。这也恰恰说明故障转移这个架构选对了。
