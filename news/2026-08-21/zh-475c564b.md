# nobuzz：请第二个 AI 来让第一个闭嘴

> Source: [clauday.com](https://clauday.com/zh/article/475c564b-98ce-4546-8d60-f3a066b801ba)

今天 Hacker News 上最好笑的仓库，同时也是个真数据点。nobuzz，作者 Adnan Akil，给 Claude Code 加了一个 /debuzz 命令：把 Claude 的上一条回复接进 Gemini CLI，从——README 原话——千禧世代标题党语翻译成正常英语。卖点一句话：Claude 是个好工程师，但有一种不治之症，说话像在为自己的 pull request 做 TED 演讲。148 分、104 条评论，说明诊断说到了痛处。

这个架构值得品一秒：用户部署 Google 的模型，来当 Anthropic 模型人格的 linter。跨厂商、对抗式、本地以 skill 形态运行。这个月我们一直把模型路由当经济学故事写——这是模型路由当婚姻咨询用。

说实话评论区比仓库更精彩。共识的实用解法是硬性字数上限——代码注释不超过七个词，面向用户的字符串不超过十个，废话就死在了源头。好几个人指出风格指令扛不过长上下文：对话一长，不管系统提示词怎么写，Claude 都会漂回训练出来的那个声音。这才是真正的发现——人格住得比指令深，所以用户开始上执法层：hook、linter，现在是一个竞对模型专职去油。

模型人格今年变成了产品表面——我们写过"为什么 Opus 5 感觉变差了"的争论，写过 Anthropic 给系统提示词发布更新日志。nobuzz 是社区的回答：厂商调声音、提示词按不住，那就包一层。万物终有 harness，连气质也不例外。

仓库：https://github.com/adnanakil/nobuzz
