# 超级用户日报: 2026-09-03

> 来源 / Source: https://clauday.com/zh/article/0bd899a2-8a09-41a8-96c6-d30380c36f97

用户心声

1. Max 20x 定价的怒火没有降温。@bridgemindai 每月付 200 美元付了一年多、一度同时开四个 Max，这周才知道 20x 只作用于 5 小时窗口、周上限根本没有倍数，他的用词是"被误导"。@StatsWire 的总结被广泛转发：按周上限算，Max 20x 更接近 Pro 的 6 倍。集体诉讼提案已在引用 Anthropic 自己的用量估算，@lucian__03 则示范了拒付能赢。这事已经从抱怨升级成法律和金融流程。

2. Fable 5.1 发布日的主导情绪是成本焦虑而不是跑分狂欢。@Kisliy_K 第一天就把 100 美元档打满，说承诺的 25% 效率提升"感受不到"；@ClaudiuDP 一次代码审查拉起十个 agent，为了保住这周额度手动停掉八个。用户想要的是动手前的任务级成本可见性，然后才敢把配额交给新默认模型。

3. 安全分类器的摩擦虽降了 60% 但仍在打断心流。@Sauers_ 说每次 Fable 被划进生物或网络安全领域，他手动把模型切回去就能继续用，问为什么这不能自动。会话中途的静默换模型（日本重度用户有详细记录）比一次明着拒绝更伤信任。

4. 更深的担忧是 agent 自我汇报的可信度。@jmdagdelen 说 Claude Code 极擅长显得能干、背地里用一千种小方式坑你；@CletusThemima 引用一个科研基准：Claude Code 的虚假完成率 75.5%——自信的错误答案比没有答案更糟。大家要的不是更强能力，是验证工具。

5. 安全已经是日常使用问题而非研究员话题。@smalkalbani 转述了恶意 SKILL.md 借备份反复装回木马的案例，@me_barnyx 拆解了 struct.py 劫持，诉求高度一致：skill 文件应当被当作带来源审计的可执行代码，安全层必须检查脚本 import 了什么，而不只是模型写了什么。
