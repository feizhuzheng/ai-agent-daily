# spec-kit 冲到 12.8 万 star，几乎每天发一个版本

> 来源 / Source: https://clauday.com/zh/article/7bdb2273-0361-4a3d-bde7-b2f5a8073a82

GitHub 的 spec-kit 一天涨了 1147 个 star，总数越过 12.8 万。一个核心主张是"你应该先把规格写清楚"的仓库能到这个数，本身就挺不寻常。它的说法叫 Spec-Driven Development：动手之前先定义要造什么，配任何 AI 编码 agent 都行。MIT 协议，Python，1795 次提交，支持三十多个编码 agent，不押注任何一家。

工作流是一串命令，每一步产出一份东西。宪章、规格、技术方案、任务拆解、然后实现。底层信念是：一句 prompt 生成代码是错误的工作单位，每个阶段都留下书面契约的多步细化才是对的。你要是眼看着一个 agent 信心满满地把错误的功能造了四十分钟，那你已经同意了。

比概念更有意思的是发版节奏。翻一下这个月的记录：0.15.0、0.15.1、0.15.2、0.16.0、0.16.1、0.16.2、0.16.3、0.16.4，一两天一个版本。而这些版本的内容说明了项目的重心挪到了哪。Copilot 集成把默认从 commands 换成了 skills。一等公民的 agent-native 运行时 hook 落地。扩展的 manifest 现在可以自带模板和脚本。扩展和预设的压缩包下载做了安全加固。现在有一整套预设生态，覆盖安全、架构、iSAQB、无障碍、跨平台和 agent 一致性治理，预设按顺序解析，命名空间化成自包含的命令。

把这串再读一遍。这已经不是一个 prompt 模板集合了，这是一个带治理层的插件运行时，而且正在打自己的供应链安全补丁。从"这里有个整理 prompt 的好办法"走到"这里有个带签名压缩包的 agent 行为包管理器"，用了大约四个月，跟 DeepSeek 那个 harness 以及每一个驾驶舱工具走的是同一条轨迹。

github.com/github/spec-kit，文档在 github.github.com/spec-kit。
