# harness 到底是个啥，终于有人讲清楚了

来源 / Source: https://clauday.com/zh/article/700a4f05-4535-4dbc-9b05-3e41015aa093

harness 这个词在这个站上已经念叨了好几个月，但一直没人把它到底指什么说明白。Earendil，就是做开源 Pi 编码 agent 的那个小团队，用一句最干净的话补上了这个洞：agent 等于 model 加 harness。模型是那颗光秃秃的大脑，harness 是它住进去的那层软件——而这层软件，恰恰是几乎没人聊、但所有人都在依赖的部分。

他们把 harness 拆成四块。一是 system prompt，相当于给模型的入职手册，告诉它你是谁、该怎么干活。二是工具，就是它能真正调用的那些代码，搜网页、跑脚本、发邮件。三是 agentic loop，让它调一个工具、看看返回了啥、再决定下一步，而不是一口气答完就完事的那套机制。四是翻译层，让同一个 harness 今天能驱动 Fable、明天能换成 GLM，不用重写。最后这块最容易被忽略，但它才是关键——它让 harness 从某一家实验室的外壳，变成谁都能换脑子的通用件。

这名字来自攀岩，而且这个类比是真管用。攀岩的安全带把你吊住、把你锁在路线上、你打滑的时候接住你。agent 的 harness 对一个本来会跑偏坠崖的模型干的是同一件事。但真正的落点是政治的，不是技术的：如果你能在自己机器上拥有并运行自己的 harness，你就保住了自主权。你不是从掌控那个 app 的实验室手里租工作流。你可以换大脑、留日志、定自己的规矩。

这篇文章出现的这一周，正好 NVIDIA 拿一个定制 harness 把 Claude Opus 5 在 ARC-AGI-3 上从 30% 拖到了 100%，Google 的 EnvHarness 又在论证环境比 agent 本身更重要。整个领域都在往一个念头上收敛：能力的单位不是模型，是模型加 harness。Earendil 的贡献是把那句大家心照不宣的话挑明了说——这两半里，harness 才是你真正能拥有的那一半。原文在 earendil.com/posts/what-is-a-harness。
