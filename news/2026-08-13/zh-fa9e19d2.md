# Bullet：不优化模型，优化循环的编码 agent

> Source: [clauday.com](https://clauday.com/zh/article/fa9e19d2-e174-4ed7-ad76-cd5065a94fb3)

今天的 Launch HN 是 Bullet，YC S26 的编码 agent，全部卖点就一个字：快。不是更聪明，是更快。创始人天天用 Claude Code，等 agent 跑完等掉了大把时间，得出的结论是模型早就够用了，问题出在模型周围那一圈机器上。

靠三个机制。路由与升级，简单步骤丢给快模型，只有任务真的配得上时才升级到大模型。搜索与获取，做定向代码检索，只捞出那几个相关文件，而不是把整个仓库铲进上下文。以及互不依赖的工具调用并行跑，不排队。单拎出来没一个是新东西。值得注意的是有一支团队把延迟当成产品本身而不是副作用，而且一边这么干一边报出 SWE-Bench Verified 95.8%。

路由这一点尤其值得说，因为它和大多数 harness 的做法是反的。今天的默认操作是什么都丢给手头最强的模型，因为这样最省事，而且没人会因此被开除。可是一次上百轮的 agent 运行，大部分内容无聊得很：读个文件、确认个路径、跑个测试。为了列一个目录去付前沿模型的价格和前沿模型的延迟，是这个行业最贵的习惯。Bullet 赌的是一个真正的路由器在墙钟时间和成本上都能赢过一个更大的模型。

时机很有意思。同一天 Cerebras 宣布 GPT-5.6 Sol 跑到每秒 750 token，那是从硬件那头打同一个抱怨。两条路通向同一个终点：agent 在你注意力还没飘走之前就答完。如果硬件那条路彻底赢了，编排上的小聪明会贬值不少。如果它还要贵着、限量预览一段时间，那 Bullet 这条路才是大多数团队真正付得起的。

私有测试中，暂时免费，无订阅。macOS 和 Linux，命令行安装或直接下载，codewithbullet.com。
