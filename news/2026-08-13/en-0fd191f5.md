# Super User Daily: August 14, 2026

> Source: [clauday.com](https://clauday.com/article/0fd191f5-93b7-4424-979d-5a95a4c87d76)

The theme that keeps surfacing is subtraction. Boris Cherny telling people to delete their CLAUDE.md files, skills and hooks every six months. A team cutting 80% of the system prompt and getting a better agent. An engineer pointing a second, smaller model at the first one purely to shorten its output. Meanwhile the sharpest cases are almost all outside the editor: a whistleblower investigation running for three weeks straight, a morning stand-up routine that dropped from ten minutes to three, an ad operation running $200k a month of spend from a terminal, and a nurse's worth of SaaS subscriptions quietly cancelled and rebuilt in-house.

@hasan_ab_hasan [Claude Code]
https://x.com/hasan_ab_hasan/status/2087615104934093191
Block 27 of his engineering series, aimed squarely at people shipping apps built by Claude Code. The scenario: an order button works in testing, then one day the spinner spins forever, the user taps again, and the first tap had actually succeeded, the response just never came back. Reads are safe to retry, writes are not, and three separate things now want to retry: the user, your retry logic, and the browser resending the form. The fix is idempotency, a key generated once when the user commits to the action and reused on every attempt, with the server storing handled keys and replaying the saved response. Stripe, Adyen, PayPal and Square all built this in because they assume your request will arrive twice. His actual point is the meta one: you do not need to write this code, you need to know the block exists so you can ask for it.

User Voice

Subtraction is beating addition, and the people closest to the tool are the ones saying it loudest. Boris Cherny's advice to delete your CLAUDE.md, skills and hooks every six months and see what the model does unaided (@shmidtqq) sits alongside 80% of Claude Code's own system prompt being cut for a better result, while the market keeps selling bigger skill packs.

Write postconditions, not procedures. The clearest formulation came from @AiDevCraft: specifying completion conditions makes output converge to the same result whether Codex or Claude Code executes it, so the portability question is declarative goals versus imperative steps, not Markdown versus Skill. @0xShoopy's account of specs precise enough that two engineers would build the same thing is the same principle at the other end of the scale.

Agents do not tell you when they are stuck, and people are building their own alarms. @kleen_pulse lost twenty-minute stretches to a silent permission prompt and shipped a TTS companion to fix it; @TheDavidTai is stuck on a Windows bypass-permission regression across three versions; @mdam10x had to build an app just to stop his laptop killing overnight runs. Observability of a running agent is still something users bolt on themselves.

Instructions decay across long sessions. @TahiGichigi found that /caveman and similar output-shaping skills drift back after enough turns, and the fix was a hook re-injecting the skill every turn. @interplanetary flags the same risk from the other direction in inter-agent messaging, more steering, probably more drift.

The fabricated-success genre is now large enough that debunking it is a service. @DaviddDotTech pushed back on the "student made $750k with Claude Code" wave with his own numbers (2,000 strategies backtested, 400 profitable, 7 in use), and @SlavaOPs traced a real Karpathy result mutating into a fake statistic through a chain of retellings. Both are more useful than the posts they correct.

Cost, not capability, is the live constraint. @aboss's three-week investigation is limited by funds rather than model quality, @gmharhar's 24-hour broadcast carried a ~$50K compute bill, @gianmauric ran a single prompt for twelve hours, and rate-limit anxiety around the expiring Claude Code limit increase ran through the day.

Eco Products Radar

Claude Code, Codex and Cursor are the constant three-way reference point in almost every workflow described today. Beyond those:

Orca - runs the same task across Claude Code, Codex, OpenCode and Cursor in isolated git worktrees so you can compare and merge the winner; mentioned repeatedly as the parallel-agent control room.

Graft - persists codebase knowledge as cards inside the repo so agents stop re-reading everything; claims 42% fewer tokens, 46% fewer tool calls and 60% less time across 162 controlled runs, MIT licensed, no embeddings.

Statewave - open-source memory runtime built around provenance rather than capacity: access controls, tamper-evident audit trails, source traceability, self-hosted, works with Claude Code, Cursor, Windsurf and MCP clients.

MCP - now the input layer rather than an integration, with Linear reporting more issues created through MCP than through its own app.

Ollama - the standard local sidecar, showing up both as a free coding backend and as the rewriting model in the claudish-to-english plugin.

Grok Build / Grok Bot - the week's new comparison target, tested against Claude Code by several people, with its own source maps leaking the harness the same way Claude Code's did.

gstack, obra/superpowers, Claude Fast - the skill-collection layer, now large enough that curation and deletion are becoming the actual skill.
