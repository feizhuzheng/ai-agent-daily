# context-mode：别让 agent 直接看工具输出

> 来源 / Source: https://clauday.com/zh/article/f3936a78-5f18-468f-9df9-594b0e41a436

吃掉 agent 上下文窗口的大头不是对话，是工具输出。一次肥大的 grep、一个啰嗦的 API 响应，三分之一的窗口就没了。context-mode，今天在趋势榜上、9 月 7 日刚有提交（20.8k star），用的是那种事后看显而易见的解法：工具输出放到沙箱子进程里跑，建索引，给 agent 一个引用而不是全文倾倒。号称最多减少 98% 的上下文。

另一半是持久化。会话状态进 SQLite 加 FTS5，BM25 检索，还能扛过 compaction——就是 agent 把自己的历史压缩成摘要、一小时后需要的细节却找不回来的那个环节。它以 MCP server 加 hooks 的形式发布，号称支持 17 个平台，Claude Code、Gemini CLI、OpenCode 有完整 hook 支持。协议是 ELv2，打算在上面做生意的先看清楚。

这是整个 harness 层从不同方向反复撞到的同一个结论：上下文窗口是稀缺昂贵的缓存，不是草稿盘。caveman 的路子是让 agent 少说话（https://clauday.com/zh/article/d9b38ea0-8972-4cd7-9aff-5a698d0a05c4），context-mode 的路子是让它少读。按需检索赢过囤在窗口里，token 账单和 compaction 丢失的数字一直在给这个结论投票。
