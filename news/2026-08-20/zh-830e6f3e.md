# Huzzah：如果提示词才是源代码呢

> Source: [clauday.com](https://clauday.com/zh/article/830e6f3e-6bdc-4c4d-badc-11d6573ba529)

每个 coding agent 会话都在扔掉自己最值钱的产物。你用斟酌过的英语解释意图，agent 写出代码，然后解释蒸发了——下次改动，你从头再解释一遍。开发者 Daniel Vaughn 的实验性编辑器 Huzzah 在 Show HN 拿了 158 分，建立在相反的前提上：提示词应该是一个你留着的文件。

具体做法：在 .hz 文件里写伪代码，声明式地描述程序该干什么。保存，Huzzah 生成你要的任何语言的真实实现。之后改伪代码，它对你的改动做 diff，只重新生成受影响的部分，不用把整份意图重喂给模型。今天的 agent 提示词是长文、命令式、一次性的——描述改动，看它发生，描述丢掉；Huzzah 的是伪代码、声明式、持久的：一份关于软件应该是什么的常设记录，生成的代码只是构建产物。示例给了 FizzBuzz、购物车和待办应用，作者也直说现在还是实验状态。

这个愿景有实打实的难题要解，头一个就是生成的代码被手改之后跟伪代码漂移怎么办——当年模型驱动开发那一代工具就是死在这个漂移上的。但方向跟认真玩 agent 的人已经在走的路是押韵的：spec 文件、CLAUDE.md、设计文档正在变成对机器的持久接口。Huzzah 只是把这个主张挑明了：持久的资产是你对问题的描述，代码是它的下游。值得注意的是,HN 评论区吵的是编译模型，没人吵前提本身。前提已经悄悄赢了。
